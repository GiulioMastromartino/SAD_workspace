What the numbers do not say

  • The 1.44× suite mean is not a claim about the demos. It is dragged down by 23 deliberately tiny surface legs (T = 6–120 s) where a fixed per-step cost dominates. Compare like for like: the demo set is 2.84×, and the per-step cost is what the parity legs measure.
  • The isolated fixture disagrees with the demo cells, and that is real. swap_speed carries a thruster plus a fuel tank; the larger symbolic system costs more per step to evaluate, so the same integrator swap buys less (1.09× at 60 s, 1.60× at 600 s). The omni win tracks how much of stock's time is SWIG message traffic, which grows with effector count.
  • The hijack ratios measure start-up, not throughput. Each leg is a fresh interpreter: ~1.3–1.6 s of stock run against ~2.0–2.3 s of import plus symbolic build, on demos whose horizon is 80–600 steps. Read them as "the port boots in about the same wall time as the demo it replaces", not as a slowdown.
  • Single shot, loaded host. Bench cells are one measurement each, no repeats, taken while the 1-min loadavg sat at 3.2. Treat single-digit-percent differences as noise; only the demo-tier and sub-1× separations are outside it.
  • Scope. Every leg mirrors through the repo's omniheyoka/swap.py loaded by path with the installed OmniVecIntegrator. These numbers say nothing about the installed wheel's own swap.py.
